# ActLedger specification

JSON Schema files and [`test-vectors/`](test-vectors/) live in this directory and are shared by both languages. Chinese prose is in [`zh-CN/`](zh-CN/README.md).

## Source of truth

This directory describes the external format the current implementation must follow. If a document disagrees with the code, change the document to match the code. Do not change protocol behavior to match a document. How the pieces fit together is summarized in [docs/en/architecture.md](../docs/en/architecture.md) and [docs/zh-CN/architecture.md](../docs/zh-CN/architecture.md). This directory gives the rules a verifier can implement on its own.

## 1. Scope and audience

The audience is authors of receipt verifiers, ledger implementations, and policy engines.

This directory specifies only what is implemented and what `verify` checks: fields, algorithms, state transitions, and the expected test vectors. The HTTP API is not implemented and is not presented here as finished.

## 3. Normative words

The keywords MUST, MUST NOT, SHOULD, SHOULD NOT, and MAY are interpreted as in RFC 2119 and RFC 8174.

## 4. Identifiers and versions

Published identifiers:

| Identifier | Code constant | Meaning |
| --- | --- | --- |
| `actledger.receipt/0.1` | `RECEIPT_V01` | Receipt 0.1 |
| `actledger.receipt/0.2` | `RECEIPT_V02` | Receipt 0.2 |
| `actledger.secrets/0.1` | `SECRETS_V` | Secrets JSONL |
| `https://actledger.dev/schema/payload-0.1.json` | `$id` of `payload.schema.json` | Payload schema |
| Policy `version: 1` | `policyDocumentSchema` | Policy document |

Before v1.0, a minor version may be incompatible. `verify` MUST validate every previously published version. After v1.0, only optional fields may be added. Changing the hash or signature input MUST increase the major version.

## 5. Terms

- **App**: one ledger instance, with `app_id` and a signing key.
- **Principal**: the person responsible for the action, `principal_id`.
- **Agent**: the agent that starts or executes the action, `agent_id`.
- **Task**: the record of one action from `prepared` to a terminal state.
- **Action**: an action type and its attributes.
- **Payload**: the parameter object given to the executor.
- **Receipt**: an append-only record of one state transition, with a hash and a signature.
- **Actor**: who wrote the receipt.
- **EvidenceRef**: an evidence reference on a receipt.
- **Assurance**: the identity-assurance level at approval time.
- **Coverage**: `recorded` or `enforced`.
- **Commitment**: an HMAC of plaintext using the task salt.
- **Salt**: 32 bytes per task. It lives only in secrets and does not enter the receipt.
- **Secrets file**: plaintext that matches commitments. JSONL. It is not distributed with receipts.
- **Crypto-shred**: delete the principal's key so that principal's secrets can no longer be decrypted.

## 6. Test vectors

Vectors are generated by `scripts/gen-vectors.ts`. Keys are random, so signatures change after regeneration. CI checks the committed vectors. It does not regenerate them and diff.

| File | Use | Expectation |
| --- | --- | --- |
| `jcs.json` | `value` to a JCS string | `jcs(value)` equals `jcs` |
| `commitments.json` | salt plus value to a commit | `commit(salt, value)` equals `commit` |
| `keys.json` | KeySet | each `keys[]` item has `kid`, `alg`, `public_key`, `created_at`, `retired_at` |
| `receipts-chain-0.1.jsonl` | 0.1 chain, 5 receipts | `ok`, warning `v01_plaintext` |
| `receipts-chain-0.2.jsonl` | 0.2 chain | `ok` |
| `secrets-0.2.jsonl` | paired with the 0.2 chain | `ok`, and at least 1 task is shredded |

## 7. Guarantee boundary

The hash chain shows that what was recorded was not changed. It does not show that everything was recorded. Actions that were not integrated are outside the guarantee. Recorded integration cannot stop a caller from bypassing a wrapped tool. Enforced integration places the check outside the process.

## 8. Change process

Changes to the external format are pull requests under `spec/rfcs/`, discussed in public for at least 7 days, and they update the schemas, the prose in this directory and in `zh-CN/`, and `test-vectors/`. A change to the receipt hash or signature input is a minor version before v1.0.

## 9. Not covered yet

HTTP API, RFC 3161 anchoring, and `policy.schema.json`.

## Consistency

The expectations in section 6 match `packages/core/test/vectors.test.ts` and `packages/core/test/canonical.test.ts`. The 0.1 vector is 5 receipts of `actledger.receipt/0.1`, `ok === true`, warning code `v01_plaintext`. The 0.2 vector is `ok === true` without secrets. With `secrets-0.2.jsonl`, `ok === true`, `secrets.checked > 0`, and `secrets.shredded >= 1`.
